Yes. If your goal is to build your own internal Kiro/Copilot-style AI development platform, it is absolutely feasible. The important point is that you are not really building an LLM-powered IDE. You are building an agent runtime + code intelligence system + IDE integration + secure execution environment.

AWS describes Kiro as an agentic IDE that converts prompts into requirements, designs, tasks, code and tests, with steering files, hooks and MCP integrations.  GitHub's current Copilot architecture similarly has agents that can modify files, execute commands, work asynchronously in sandboxes, create branches and PRs, and integrate MCP/tools. 

For your environment, I would build something like this:

So your V1 should be a VS Code extension + backend agent.

15. The actual agent loop

This is the core algorithm.

while task_not_complete:

    observe()

    plan()

    choose_tool()

    execute_tool()

    inspect_result()

    validate()

    if failure:
        diagnose()

        fix()

    if tests_pass:
        continue

    if task_complete:
        stop

Example:

User:
"Add employee leave cancellation API"

Agent:

1. Search Leave module
2. Find LeaveController
3. Find LeaveService
4. Find LeaveRepository
5. Inspect DB
6. Inspect existing APIs
7. Create plan
8. Modify service
9. Modify controller
10. Add validation
11. Generate tests
12. Run mvn test
13. Test fails
14. Read failure
15. Fix implementation
16. Run tests
17. Tests pass
18. Show diff

That loop is the real product.

Don't think:

> "How do I build an AI that writes Java?"
